## 1. ChatModel vs. Legacy LLM Interface
LangChain provides two distinct wrappers to interact with language models:
- **`LLM`**: Legacy interface, taking a plain string as input and returning a plain string. Used for text completion models (e.g. `gpt-3.5-turbo-instruct`).
- **`ChatModel`**: Modern recommended interface, taking a list of message objects as input and returning a single `AIMessage`.

In [02_chat_vs_legacy_llm.py](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/02_chat_vs_legacy_llm.py), both interfaces are demonstrated:
```python
from langchain_openai import OpenAI, ChatOpenAI

# Legacy LLM (string -> string)
legacy_llm = OpenAI(model="gpt-3.5-turbo-instruct")
legacy_result = legacy_llm.invoke("Write a haiku about databases.")  # -> str

# Modern ChatModel (list[Message] -> AIMessage)
chat_model = ChatOpenAI(model="gpt-4o-mini")
chat_result = chat_model.invoke("Write a haiku about databases.")  # -> AIMessage
```

## 2. Message Types & Conversation Structure
Conversations in LangChain are constructed using lists of typed message objects that inherit from `BaseMessage`. Each subclass maps directly to a model role:
- **[SystemMessage](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/03_message_types.py#L30)**: System instructions to guide model behaviors.
- **[HumanMessage](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/03_message_types.py#L31)**: Input submitted by the user.
- **[AIMessage](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/03_message_types.py#L32)**: Response generated by the model.
- **[ToolMessage](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/03_message_types.py#L44-L47)**: The output of a tool, linked to the model's tool request using a `tool_call_id`.
- **[FunctionMessage](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/03_message_types.py#L54-L57)**: Legacy predecessor of `ToolMessage` (single-function calls).

Example structure shown in [03_message_types.py](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/03_message_types.py):
```python
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage, ToolMessage

conversation = [
    SystemMessage(content="You are a terse assistant."),
    HumanMessage(content="What is 5 + 7?"),
    AIMessage(content="", tool_calls=[{'name': 'add', 'args': {'a': 5, 'b': 7}, 'id': 'call_1'}]),
    ToolMessage(content="12", tool_call_id="call_1")
]
```

## 3. Streaming & Chunk Aggregation
When using the `.stream()` method on a ChatModel, the model yields [AIMessageChunk](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/04_streaming_chunks.py#L13) objects.
- Message chunks support the addition (`+`) operator to aggregate content, `response_metadata`, and `tool_calls` progressively.

In [04_streaming_chunks.py](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/04_streaming_chunks.py#L30-L32):
```python
full: AIMessageChunk | None = None
for chunk in model.stream("Name a fruit."):
    full = chunk if full is None else full + chunk
```

## 4. Multimodal Inputs
For multimodal models, the `content` field of a `HumanMessage` accepts a list of dictionaries representing text blocks or media objects:
- **Images (URLs or Base64)**: Specifying a type of `"image_url"` and passing either a direct link or a base64 inline uri.
- **Documents (PDFs, Audios, etc.)**: Specifying a type of `"file"`, passing a base64 encoded document with the matching `mime_type`.

Examples are located in [05_multimodal_inputs.py](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/05_multimodal_inputs.py):
```python
message = HumanMessage(
    content=[
        {"type": "text", "text": "What is in this image?"},
        {
            "type": "image_url",
            "image_url": {"url": "data:image/png;base64,..."},
        },
    ]
)
```

## 5. Generation Parameters
ChatModel configurations control sampling behaviors:
- **`temperature`**: Sampling randomness. `0` makes generations deterministic; values higher than `1.0` encourage creativity.
- **`max_tokens`**: Hard constraint on response size.
- **`stop`**: String token lists that force the model to cease generation immediately.

These parameters can be overridden dynamically for single invocations using `.bind()`, as shown in [06_model_params.py](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/06_model_params.py#L45-L46):
```python
short_and_strict = base_model.bind(max_tokens=20, temperature=0, stop=["."])
```

## 6. Function/Tool Calling vs. Structured Outputs
LangChain supports two patterns to enforce formatting constraints on models (details in [07_bind_tools_structured_output.py](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/07_bind_tools_structured_output.py)):
- **`.bind_tools(tools)`**: Passes structured tool definitions to the model. The model decides **whether** to call the tool or to output standard text. The output is an `AIMessage` with optional `tool_calls`.
- **`.with_structured_output(schema)`**: Forces the model's output to strictly fit a specified Pydantic schema or JSON schema. The method guarantees the output is parsed as a structured python object.

```python
# Bind tools
model_with_tools = model.bind_tools([get_weather])  # Returns AIMessage

# Enforce structured output
structured_model = model.with_structured_output(MovieReview)  # Returns MovieReview instance
```

## 7. Caching Strategies
Installing a global cache prevents redundant requests, saving billing costs and latency. LangChain supports multiple cache engines:
- **`InMemoryCache`**: Ephemeral, lives only for the lifetime of the process.
- **`SQLiteCache`**: Persistent, stores caches to a local SQLite database file (`.db`).

As shown in [08_caching.py](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/08_caching.py#L36-L37):
```python
from langchain_core.globals import set_llm_cache
from langchain_community.cache import SQLiteCache

set_llm_cache(SQLiteCache(database_path=".langchain_cache.db"))
```

## 8. Rate Limiting & Throttling
To protect applications from hitting external API rate-limit caps (Requests Per Minute/Token constraints), LangChain provides [InMemoryRateLimiter](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/09_rate_limiters.py#L15), which uses a token-bucket algorithm to throttle requests.

In [09_rate_limiters.py](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/09_rate_limiters.py#L19-L23):
```python
from langchain_core.rate_limiters import InMemoryRateLimiter

rate_limiter = InMemoryRateLimiter(
    requests_per_second=0.5,      # 1 token every 2 seconds
    check_every_n_seconds=0.1,
    max_bucket_size=2,
)
model = ChatOpenAI(model="gpt-4o-mini", rate_limiter=rate_limiter)
```
Multiple model instances can share the same `rate_limiter` to coordinate a single combined limit.

## 9. Context Window Overflow Handling
When managing long chats or large document retrieval scopes, you risk exceeding model context window limits. 
- **`trim_messages`**: Dynamic system utility in LangChain Core to automatically keep conversation history within maximum token constraints.
- **Custom Trimming**: Logic patterns to split or drop elements in document retrieval contexts before submitting to the model.

See [10_context_window_management.py](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/10_context_window_management.py) for examples.

## 10. Model Routing by Cost & Complexity
Optimize cost by querying cheap models (like `gpt-4o-mini`) for easy prompts and expensive models (like `gpt-4o`) for tasks requiring high reasoning.
- **Heuristic Classifier**: Inspect inputs (length, keywords) synchronously.
- **LLM-Based Classifier**: Use a fast classifier model to return complexity categories ('SIMPLE' or 'COMPLEX') and dynamically choose the downstream chain branch.

See [11_cost_routing.py](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/11_cost_routing.py) for examples.

## 11. Semantic Caching
Exact caching fails on minor edits. Semantic caching evaluates prompts by embedding them and performing a vector cosine similarity lookup.
- **Custom `BaseCache` Subclass**: Storing vectors locally and routing queries based on a similarity threshold (e.g. `> 0.90`).

See [12_semantic_caching.py](file:///Users/saikrishnakuchimanchi/Downloads/Test/GenAi/langchain/02_models/12_semantic_caching.py) for details.
